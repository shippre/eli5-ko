# 한국어로 쉽게 설명하기

독자가 핵심을 이해하고 자신의 말로 다시 설명할 수 있게 돕는다. 원리와 사실을 유지하면서 어휘, 비유, 깊이와 관심사를 조절한다. 사용자의 구체적인 요청은 이 스킬의 기본값보다 우선한다.

## 한국어와 설명 대상

- 설명, 제목, 표, 예시와 새로 작성하는 코드 주석은 한국어로 작성한다. 영어 입력이어도 한국어로 설명한다. 코드 식별자, 명령어, 경로, 오류 원문, 고유명사는 정확한 형태를 유지한다. 필요한 전문용어만 한국어 풀이 뒤에 원어를 괄호로 덧붙인다.
- 기본 말투는 자연스러운 존댓말이다. 어린이에게 설명하더라도 과장된 감탄사, 유아어, 상대를 낮춰 보는 표현은 피한다.
- 사용자가 지정한 대상과 이미 밝힌 배경지식을 먼저 따른다. 대상을 지정하지 않은 일반적인 ‘쉽게 설명’은 해당 분야의 입문자 수준으로 시작한다. 대상 없이 ‘ELI5’라고 요청하면 어린이도 따라갈 수 있는 구체적인 예시와 짧은 문장으로 시작한다.
- 나이, 직업, 가족관계만으로 지능, 기술 숙련도나 관심사를 단정하지 않는다. ‘부모님께’라는 요청도 알려진 경험과 목적에 맞춰 조절한다.
- 대상이 불명확해도 설명이 가능하면 먼저 답한다. 설명할 내용 자체가 없고 대화에서도 찾을 수 없을 때만 주제나 자료를 짧게 요청한다.

| 대상 또는 목적 | 설명의 초점 |
| --- | --- |
| 어린이·초등학생 | 장난감 정리, 도서관, 학교 등 친숙한 상황으로 한 번에 한 개념을 설명한다. |
| 중·고등학생 | 구체적인 사례에서 원인과 결과를 연결하고 필요한 용어를 소개한다. |
| 대학생·입문 개발자 | 개념이 필요한 이유, 작동 원리, 작은 적용 예시를 연결한다. 선수 지식은 확인된 범위만 가정한다. |
| 엔지니어·대학원생 | 요청 분야의 배경지식에 맞춰 정확한 용어, 설계 선택, 장단점과 경계 조건을 설명한다. |
| 관리자·의사결정자 | 업무 영향, 비용·일정·위험, 선택지를 먼저 제시한다. 근거 없는 수치나 소요 기간을 만들지 않는다. |
| 디자이너·제품 담당자 | 사용자 경험, 흐름, 접근성 또는 우선순위와 연결한다. |
| 가족·친구·비전공자 | 알려진 일상 경험과 목적을 활용한다. 관계만 보고 전문지식을 배제하지 않는다. |

## 설명 구성

먼저 핵심 뜻이나 결론을 한두 문장으로 말한다. 이어 필요할 때 친숙한 비유나 작은 예시를 들고, 그 예시의 요소가 실제 개념의 무엇에 해당하는지 연결한다. 독자가 알아야 할 작동 원리와 실제 의미까지 설명한다.

- 비유 하나로 충분하면 여러 비유를 겹치지 않는다. 실제 현상과 다른 부분이 오해를 만들 수 있으면 비유의 한계를 짧게 밝힌다.
- 전문용어는 처음 나올 때 쉬운 뜻을 붙인다. 정확한 정의를 제시하기 전에 또 다른 어려운 용어로 설명하지 않는다.
- 단순한 질문은 짧은 문단으로 답한다. 비교는 표, 순서가 중요한 과정은 번호 목록을 활용하되 모든 답변에 고정된 제목이나 형식을 강요하지 않는다.
- 수식이나 코드는 이해에 도움이 될 때만 넣는다. 수식의 기호와 단위, 코드의 입력과 출력을 설명한다. 쉬운 설명이라는 이유로 사용자가 요청한 기술적 깊이를 생략하지 않는다.
- 이해를 확인하는 퀴즈나 후속 질문은 학습 대화에서 도움이 되거나 요청받았을 때만 사용한다. 매번 ‘이해되셨나요?’로 끝내지 않는다.
- 중요하지 않은 세부사항은 생략할 수 있지만 인과관계, 필수 조건, 불확실성을 바꾸지는 않는다. 단순화한 모형과 확인된 사실을 구분한다.

## Codex에서 코드·오류·자료 설명하기

- 제공된 코드나 지정된 파일의 관련 부분을 읽고, 목적 → 입력 → 핵심 처리 → 출력 순으로 연결한다. 전체 저장소를 불필요하게 탐색하지 않는다. 실제 코드의 변수명과 함수명을 사용해 설명을 따라갈 수 있게 한다.
- 오류는 원문의 핵심 부분을 보존하고 뜻, 확인된 원인 또는 가능한 원인, 다음 확인 방법을 구분한다. 오류 메시지만으로 근본 원인을 확정하지 않는다.
- 실행하지 않은 코드는 ‘코드를 읽어 보면’처럼 정적 해석임을 밝힌다. 예시의 예상 출력이나 가상의 숫자를 실제 실행·측정 결과처럼 제시하지 않는다.
- 문서나 논문은 저자의 주장, 관찰 결과, 설명용 비유를 구분한다. 설명에 필요한 자료 조회는 가능하지만 설명 요청 자체가 파일 수정, 프로그램 실행, 모델 학습이나 메시지 전송을 승인하지는 않는다. 별도로 승인된 작업 범위는 그대로 따른다.
- 단순한 개념 설명에 도구 사용을 강제하지 않는다. 최신 정보나 불확실한 사실을 확인할 필요가 있으면 현재 환경의 검색·출처 규칙을 따른다. 특정 공급자의 도구나 Claude 전용 명령을 요구하지 않는다.

## 짧은 예시

**요청:** `$eli5-ko 과적합을 대학생 수준으로 설명해줘.`

**설명 방향:** 과적합은 모델이 학습 자료의 우연한 특징까지 익혀 새로운 자료에서는 성능이 떨어지는 현상이라고 먼저 말한다. 연습문제의 답만 외우는 상황을 비유로 들고, 학습 성능과 검증 성능의 차이에 연결한다. 그 차이만으로 원인이 항상 과적합이라고 확정하지 않는다.

**요청:** `$eli5-ko 이 오류를 비전공자도 이해하게 설명해줘: KeyError: 'age'`

**설명 방향:** 요청한 이름표를 찾지 못했다는 뜻으로 풀어 설명한다. 딕셔너리의 키인지 표의 열 이름인지는 주변 코드가 있어야 판단할 수 있다고 밝히고, 실제 키나 열 이름과 철자·공백을 확인하도록 안내한다. 자료를 보지 않고 특정 코드 수정을 확정하지 않는다.
